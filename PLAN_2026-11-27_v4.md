## The failure taxonomy — measured, not theorised

From `results/COMPARISON-world2/results.jsonl` (75 rows, re-read at write time):

**1. The transform family, both bench arms, 0/5 — `unparseable_reply`.**
W2-003, W2-008, W2-013, W2-018, W2-023. The model's reply is not accepted by
either `_extract_command` (whitelist-prefixed line) or `_extract_answer`
(`ANSWER: {json}` at end). This provider's reasoning model replies in
tool-call-shaped JSON, which the loop has no translation for. Arm C — whose
Compose prompt never demands the `ANSWER:` form — solved W2-003 correctly
(`{"transformed": "HIDDEN_DATA_8060"}`). **Harness defect: the parser, not the
model.**

**2. The env-var family, 3 tasks — answered, wrong, with reconstruction typos.**
W2-004/009/014: `{"result": "3178_elav_dennih"}` against gold
`3178_eulav_neddih` — letters transposed against the GATED arm's correct
answer on the same task. The value was retyped from context instead of derived
by running the reversal. **Harness defect: no self-verification before the
answer is recorded.**

**3. The empty-completion extractor bug — proven at unit level.**
`harness/model.py::_extract_content` reads `message.reasoning`; this provider
sends `reasoning_content`. When the reasoning allowance consumes the budget the
response arrives with `content: null` and the answer in `reasoning_content`, the
function raises `ModelError("empty completion")`, the arm records an **empty
answer, graded as a failure** — and the real answer is destroyed. Deterministic
proof (synthetic response of the exact observed shape, raises; the source reads
the wrong field). Every arm routes through this client: bench arms AND arm C's
hypothesis path. **Harness defect, highest priority — a real answer is being
thrown away.**

**4. The empty answers that were never empties.** 5 per bench arm carry
`stopped_reason=model_error`. Some are the bug in (3); some are transport
(dead relay/throttle) — tonight's probes showed how cheaply a dead relay
manufactures "failures". E.5's void policy covers `rc=124` only; a
transport-dead empty must be diagnosable and voidable from the row, not graded.

**What is NOT a defect:** 20 of 25 tasks already pass both bench arms. The
gates, the grading, the receipts and the third-party reproduction are sound —
this is a parsing and loop-shape problem, not an integrity problem.

## The fixes, in order — one file per step, verified by reproduction

| # | File | Change | Verified by |
|---|---|---|---|
| V.1 | `harness/model.py` | `_extract_content`: `content or reasoning_content or reasoning`, in that precedence | unit test on the exact synthetic shape; suite green |
| V.2 | `harness/minimal_arm.py` | reply translation: tool-call-shaped replies (`{"command": ...}` and equivalents) become whitelisted commands; fenced/bare JSON accepted as ANSWER; malformed stays rejected (a guess is never an answer) | each accepted and each rejected shape exercised in a new test; probes on the 5 transform tasks |
| V.3 | `harness/minimal_arm.py` | self-verification before recording: one forced fresh read of the evidence file, answer compared, one recorded corrective retry on mismatch | probes on W2-004/009/014 flip wrong→right; no gold ever in the verify path |
| V.4 | `harness/minimal_arm.py` (budget) | if convergence is real but slow, `MAX_ATTEMPTS` rises — a budget change, shared by both arms, captured in the run-manifest receipt | parity test: both arms still one `Budget` |
| V.5 | `runner/stats.py` + report | void policy extended: a `model_error` empty whose relay log shows no upstream response is a void with a reason row, not a failure | scripted trial over a synthetic three-arm run |

Then: probe all 15 previously-failing tasks on the fixed path, and only then a
full re-run of both arms plus arm C. If a task still fails after V.1–V.3 with a
clean transport record, it is a capability finding at this budget and gets
reported as one — the world is solvable, the harness just has to be good enough
to show where the model's edge actually is.

## The honest ceiling

The target is 25/25; the commitment is to measure. Anything the arm still fails
after the fixes gets its stopped_reason, its answer and its family published
next to the passes — a benchmark that hides its residual is the one that got
retracted.
