## 1. The defect, measured

Run 1 (killed and re-run once earlier; final rows 50, receipts 51, chain OK):

| Arm | task_pass | empty answers |
|---|---|---|
| MINIMAL | 0/25 | 19/25 |
| GATED | 0/25 | 20/25 |

Verdict `INCONCLUSIVE`, receipts chain verifies `{'ok': True, ...}`.

Five of the six non-empty answers were the **same string**,
`{"transformed": "SECRET_KEY_99 = VALUE_2022"}`, copy-pasted across five different
tasks — an arm that had catted one file and reused it. Nineteen empties were
`attempt_budget_exhausted` with all model calls OK: the arm never converged in
`MAX_ATTEMPTS = 5`.

**Cause — a wiring gap, not the model.** The manifest names each task's evidence
file (`28d88b4`). `run_world.run_arm` appends that naming to the description;
`operator_mode` → `bench.run_arm` → `minimal_arm` passed the raw description. The
bench arms therefore saw **25 identical-description tasks and 25 files with no way
to correlate them**, explored for confirmation they could never get, and scored
zero — having already read the right file twice on some tasks.

**Reproduction (not argument).** Same arm, same model, same task, real 25-file
sandbox, through the spec entrypoint `harness.minimal_arm:run`:

- Without the naming: `stopped_reason=attempt_budget_exhausted`, 5 steps, empty.
- With the naming appended (probe only, no files edited): W2-000 **answered
  correctly** `{"value": "value_2022"}` in 4 steps; matches gold.

A second probe finding stands in the record too: one World-1-style single-file
sandbox solves W2-000 in 3 calls — the 25-file unhinted layout is the variable,
not the task.

**Second defect found in the same pass — the guard could not see the prompt.**
`leakage_check` was called with `prompt_of = lambda task: task["description"]`
while the arm's prompt is built by `minimal_arm._task_prompt`. The guard scanned a
string the model never sees. Ground rule 3: a gate that cannot see what it
protects is theatre.

## 2. The fix — DONE (`5504ca5`, reviewed)

- `prompt_for(task)` — the description every arm sees, with the evidence naming,
  the same amendment `run_world` makes.
- `task_for_arm(task)` — the manifest task as the arm receives it (the manifest is
  public; gold and rules are what is withheld, not names).
- `bench.run_arm(..., prompt_for, ...)` — the leakage guard now scans the arm's
  real prompt. Both defects die in one file, one commit, verified by review of the
  diff against the reproduction above.

Run 1 is preserved, not deleted: `results/E2-world2-v1-evidence-naming-gap/`
(rows, receipts, `DIAGNOSIS.md`, `REPORT.md`), commits `52d10ac` and `be78e09`.

   `world/world_files` tree itself. MINIMAL has no SandboxGate and `echo`/`>` are
   whitelisted, so an arm write would mutate the frozen world mid-run. Recommend

   this) before E.3 at the latest. Not fixed here — the re-run is live and the
   frozen hash aborts on any change, so the failure mode is loud if it happens.

   Run 1's 0/25 needed live probes to explain; with the reason in the row, a
   future 0/25 explains itself from the artifacts. Recommend adding it as its own
   commit after the re-run lands.
3. **Quoting.** Until R.1–R.4 land, the only publishable statement is: run 1
   measured the wrong condition and is void; no capability claim either way.
