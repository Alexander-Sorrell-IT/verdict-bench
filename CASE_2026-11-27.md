# THE CASE FOR ALL THAT IS LEFT — verdict-bench, 2026-11-27

Why each remaining item exists, what it buys, and what comes back if it is skipped.
Written against the verified state: HEAD `06a79dd` (the fix and all three open
decisions landed), re-run attempt #3 in flight (PID 238801), run 1 preserved with
its diagnosis. Nothing here is estimated where it could be measured.

---

## The frame

The instrument exists to answer one question defensibly — *can an arm generalize
under frozen-world, matched-budget, gold-graded conditions?* — and to make the
answer survive someone who is not the author. The definition of done
(`REMAINING_WORK.md` §6) is the whole test: frozen hash before any arm starts,
budget consumed within tolerance, no answer formula in any prompt the model sees,
every grade hashed to withheld gold and chained, an independent grader produces
the verdict, and **the chain re-verifies offline, by someone who is not you, from
committed code alone.**

Every remaining item below is a load-bearing clause of that sentence. This is not
a backlog; it is the difference between a result and an assertion — and this repo
has already retracted one result for exactly that difference.

## The items

### 1. A completed run on the fixed instrument (the live re-run)

**The claim it buys:** the only number anyone will ever quote — pass@1 for each
arm on World 2 under the frozen world, matched budget, relay-recorded model route.

**What skipping it costs:** nothing to skip — without it there is no result at
all. The first run measured a wiring defect, not an arm: 0/25 with 19 empty
answers because the arms saw 25 identical-description tasks and 25 uncorrelated
files. The fix (`06a79dd`) is verified by reproduction, not by argument, but the
reproduction was a probe — probes are not runs. Only a full run, both arms, on the
frozen hash, produces a number that satisfies the definition.

**The precedent it answers:** the retracted 25/25 — a number that could not be
regenerated from committed code. This run is the generation mechanism for a number
that can be.

**Cost:** ~55 minutes of API at the measured pace (arm 1 ≈ 26 min, arm 2 ≈ 29
min). Already in flight; no further operator time until it lands.

**Done looks like:** 50 rows, `stopped_reason` on every row, receipts chain `ok`,
budget respected within tolerance, verdict from `grade_run` — nothing hand-typed.

### 2. E.3 — the Harness² comparison (arm C)

**The claim it buys:** the actual comparative claim the instrument was built to
make — this repo's arm shapes vs the Google Harness² shape, same world, same
model, same budget. Without E.3 the project has runs but no comparison, and the
purpose stated in the plans (a defensible position against Harness²-style agents)
is simply unmet. A benchmark with one arm family is a harness, not a benchmark.

**What skipping it costs:** E.2 alone says "these arms score X on World 2." The
question anyone will actually ask — *does a different agent shape do better on the
same tasks under the same money?* — stays unanswered, and every hour spent on
budgets, parity and the sealed grader was spent to answer precisely that.

**Precedent:** parity was structural from the start (one `Budget`, one client —
commit `e0c441c`) specifically because a launcher once gave one arm 4× the output
allowance. E.3 is where that parity gets spent.

**Cost:** arm C is built and offline-tested (`bdb1138`); the run is ~1–2 h API
once wired into the run path on the fixed code.

**Done looks like:** arm C's rows in the same shape as the bench arms', same
frozen hash, same budget object, parity of spec recorded beside them.

### 3. E.5 voids + the generated report (F)

**The claim it buys:** the right to publish a number at all — every void carries a
reason row, and the report is generated from the receipts, never written by hand.

**What skipping it costs:** the exact failure that got the last result retracted.
An INCONCLUSIVE or a partial run quoted without its void rows is the
"manufactured 25/25" failure mode wearing different clothes. The report's
disclosures (model and endpoint, voided runs, what the world-1 re-run cannot
reproduce, what the gates cannot check) are the difference between a result and a
claim.

**Cost:** minutes. `report.py` regenerates byte-identical from committed
artifacts — it was built before the runs precisely so no API time goes to
debugging the report script.

**Done looks like:** run 1's rows carry the void reason (superseded: the
prompt-parity defect, fixed in `06a79dd`); the new report regenerates from the new
receipts alone.

### 4. Banking: commit the evidence, take the backup

**The claim it buys:** the chain of custody that makes every other item auditable
— rows, receipts and log committed, a tar of the full tree including `.git`, so a
restore is a restore and not a reconstruction.

**What skipping it costs:** the E.2 lesson already paid for once: rows that exist
only in a live process are not evidence. Per-task writing and receipting exist
so a killed run costs nothing — but only if what survives gets committed before
the next relaunch's `rm -rf`. (This bit us at 02:51: attempt #2's in-flight state
was wiped by attempt #3's `rm -rf` because nobody had banked it. v21 caught that
intermediate state by luck of timing, not by design.)

**Cost:** minutes per run.

**Done looks like:** each run's rows + receipts + generated report in one commit;
`verdict-bench_AFTER_<date>_vNN.tar.gz` verified by listing its contents, not
asserted.

### 5. Offline re-verification by a third party

**The claim it buys:** the last clause of the definition — the whole chain
re-verifying from committed code alone, by someone who is not the author.

**What skipping it costs:** everything. Without it, the benchmark's central claim
("no answer formula in any prompt; grades hashed to withheld gold; verdict from an
independent grader") rests on the author's word. The audit that started this
whole correction (`AUDIT_2026-11-25.md`) exists because a trusted-author claim
turned out to be unreproducible. A benchmark of generalization that cannot
survive a stranger's clone-and-run has not generalized anything.

**Cost:** operator time only — a clean-room run from `git archive HEAD`: gates,
solver, tests, then the report regeneration against the committed receipts.

**Done looks like:** a fresh checkout reproduces 68/68 gates, the suite, and the
verdict line from the committed receipts with no access to this machine.

## What is NOT left (settled since the plan was written)

All three open decisions from `PLAN_2026-11-27_v3.md` landed in `06a79dd` while
the runs were finishing — verified by reading the diff:

- the leakage guard scans the arm's real prompt (`prompt_for` renders through
  `_task_prompt`, not a string near it) — ground rule 3, no longer theatre;
- the run works in a sandbox copy, not the frozen tree (the freeze-abort failure
  mode should not exist, not merely be loud);
- rows carry `stopped_reason` and `gate_blocks`, so the next 0/25 explains itself
  from the artifacts instead of needing live probes like the ones that diagnosed
  this one.

What is NOT claimed, and must not be: any number from run 1, any number from the
re-run until it lands, and anything at all from the gates beyond "structurally
sound." The gates' own coverage block says it: they cannot check that the tasks
are hard, that gold is correct, or that the run was fair. Those are what the runs
and the third party are for.
