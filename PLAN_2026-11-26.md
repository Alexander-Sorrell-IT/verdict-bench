### Known parity defects to fix, not inherit

- `runner/run_arm.sh` sets `OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX=32000` **for Arm B only**. That is an output-budget asymmetry baked into the launcher: Arm B can emit 4× the tokens Arm A can. Either normalise it for both arms or disclose it in the report — an undisclosed asymmetry invalidates the head-to-head.
- Arm B's `opencode.json` pins one model with no fallback; Arm A's config does the same. Good. Keep it that way — a silent fallback roster is how "same model" quietly becomes "different model".
- Relay logs one line per call. It must not log `Authorization` headers.

### Declared support boundaries

- OpenAI-**compatible** endpoints only. Anthropic-native and Gemini-native payloads need an adapter; the registry says so rather than promising coverage that doesn't exist.
- Arm A runs in-process (no Docker). Arm B needs OpenCode + its harness tree. That install difference is a disclosure, not a hidden one.
- Free-tier rate limits throttle a run. The relay's single global throttle keeps it fair across arms, but a degraded key must show as 429 counts in the manifest, not as a quiet failure — the exact failure shape that produced 25/25.
